# concept-diagram — 概念图的画法

图是用来**看懂**的，不是用来**读完**的。图形承载信息，文字只补图形说不出的那一点。

## 流程

1. **先找领域已有的标准记号，别自创。** 序列/时序 → timeline；存量与流量 → stock-and-flow（Forrester：方框=存量、蝴蝶阀=流量、虚线胶囊=系统边界）；业务过程 × 一致性维度 → Kimball bus matrix。动手前先说清「用哪套记号、为什么它配这份内容」，以及放弃了哪套、为什么。
2. **先出 2–3 个变体给我挑，别动真文件。** 每个变体只喂数据子集。变体之间的差别必须是**画法**之别，不是配色之别。
3. 定稿后落到 scratchpad 单页 HTML，用 `ui-dev-bridge` skill 自带的 `tools/mock-serve.py` 起服务（见该 skill），给我 `http://localhost:8777/<x>.html` 点选批注。我满意了再拷进仓库；**提交要等我说**。

## 硬规矩

**粒度必须对齐层级。** 一条指标的事就贴在那个节点里；一类记号的事进图例；只有整张图的范围与机制才独立成段。**把节点级的事升成与主干平行的一节，是最常犯的错**；反过来把页级的事塞进某个节点里同样是错。

**属于主干的东西必须画在主干上。** 判据是模型自己的守恒式/依赖式——等式里并列的项，图上就得并列。「另起一张卡片放旁边」等于承认你没画出它和主体的关系。支路要有**真的连接线**连回分叉点。

**同一件事只标一次。** 节点已经被主干上的记号标过，就别再描边、再加图标。三重标记 = 拥挤。

**同类节点包装一致。** 节点 + 它挂的指标是一个统一形状；所有链、所有节点共用同一套。

**对齐是硬要求，不是审美。** 同级节点同一基线，连接线对准列心。差 7px 也是 bug。

**文字只写图形说不出的。** 每处注 ≤ 2 行。细节属于代码与档案，不属于图。收尾时逐句问：删掉它图还看得懂吗？看得懂就删。

**我指一处 = 一类。** 收到批评先在全篇找同类，一起改，别只改被指的那个。

## 技术约定

- 单页自包含 HTML：无外链（字体走系统栈或 data URI）。
- 双主题都要：token 化，`prefers-color-scheme` 与 `:root[data-theme="dark"|"light"]` 都覆盖。
- 记号用 CSS 画（border 三角做阀门、渐变做液位），不手写长 SVG path。
- 宽内容自带 `overflow-x: auto`，body 永不横滚。
- 中文文案。

## 验证（改完两步都做）

1. **量**：无横向溢出、同级基线一致、连接线 dx=0、主干/时间轴连续（同一条轴上 band top 唯一）。
2. **看**：截图或亲眼过一遍整页。**只量不看会漏掉结构性破损**——量的是几何，坏的往往是 DOM 嵌套，几何还是绿的。
